# Перенос CycleConnect на новый VPS

CycleConnect перенесён с общего сервера `front` на новый VPS `cc`.
На `front` остаются другие проекты; их не переносить и не останавливать.
Исходный сервер и его данные сохраняются для отката.

## Актуальное состояние на 01.11.2026

- Native Gemini подключён для чата и JSON: `gemini-3.5-flash-lite`; embeddings
  используют `gemini-embedding-2` размерности 1024. На новом сервере заданы
  `LOCAL_AI_ENABLED=false` и `EMBEDDING_PROVIDER=gemini`. AI-проверки: 58 тестов,
  TypeScript, production build и e2e-поиск двух маршрутов прошли; начальная
  финальная переиндексация завершена для 30 из 30 маршрутов.
- Отдельный `cc-egress` systemd-туннель через польский узел настроен с
  ограниченным SSH-ключом. SOCKS доступен на `172.18.0.1:1080`; релейные порты
  `8444` (Telegram) и `8445` (Gemini). Приватные Deno endpoints gateway —
  `8087` и `8088`. Перенесено 4 GB SRTM.
- В приватной сети проверены Realtime, Edge Functions, Studio и Meta. Auth,
  Storage, API и браузерные проверки прошли. Задержки возникали при одновременном
  чтении с HDD, не из-за нехватки RAM; после тяжёлых операций проверки всех
  сервисов проходили через 15 секунд.
- Текущий layout: приложение и env в `/opt/cycleconnect`, compose в
  `/opt/cycleconnect-stack/compose.json`, проект `cc-stage`; контейнеры имеют
  префиксы `cc-stage-*`, Studio/Meta — `supabase-*`. Backend-порты закрыты;
  наружу опубликованы только gateway `80/443` и SSH `22`.
- Финальные dump и Storage-копия находятся в закрытом
  `/root/cycleconnect-migration/final/`; полное восстановление прошло, сверены
  Auth, Vault, все 109 RLS-политик, ACL и хеши ролей. Все 186 файлов Storage
  скачаны через API и сверены по SHA-256. Старые app и Supabase на `front`
  остановлены, cron и watchdog CycleConnect отключены; данные сохранены.
  Другие проекты не менялись, `ksumax.dev` продолжает отдавать HTTP 200.
- Все четыре A-записи Cloudflare — apex, `api`, `studio`, `www` — переключены
  на `185.186.142.168`, DNS only, TTL Auto. Старый Caddy пересылает запросы
  CycleConnect на новый VPS, сохраняя Host/SNI; это обслуживает старый DNS-кеш.
- Релей Poland `:18443` переключён на новый VPS. SMTP TLS/login и Realtime
  WebSocket join прошли. Telegram API: pending updates 0, ошибок нет;
  тестовый пустой webhook прошёл через vdsina2 с проверкой TLS и ответом `200 ok`.
  Реальные письма и Telegram-сообщения не отправлялись.
- [PR #7](https://github.com/KsuMax/cycle_connect/pull/7) прошёл CI и слит
  в `main`; [первый автоматический deploy](https://github.com/KsuMax/cycle_connect/actions/runs/41248782291)
  завершился успешно. После перезапуска AI Search снова вернул маршруты без ошибок.
- Резервное копирование установлено и включено: `cc-backup.timer`, ежедневно
  в 03:00 Europe/Moscow с задержкой до 10 минут, хранение 14 дней.
  Проверены dump, архивы и SHA-256; из свежей копии восстановлены все 186 файлов
  с совпадением байтов и xattrs. Конфигурационный архив содержит bootstrap SQL,
  Kong, Auth templates, функции, Deno cache, TLS, env и systemd-настройки.
  Разовая копия сохранена на Mac в `~/.codex/private-backups/cycleconnect/`,
  режим файла 600; все пять внутренних контрольных сумм совпали.
- Включены ровно два исходных pg_cron-задания (часовое и 06:00 GMT),
  `cron.launch_active_jobs=on`. `cc-finish-events.timer` заменяет старый host cron
  в 09:30 Europe/Moscow.

## Этапы

1. **Сервер и стек — работают.** Backend-порты не опубликованы.
2. **Финальная копия и полное восстановление — проверены.** Финальные dump и
   Storage-копия сверены, восстановление Auth/Vault/RLS/ролей прошло.
3. **AI и интеграции — проверены на новом VPS.** Gemini chat/JSON, embeddings,
   туннель и финальная переиндексация 30/30 работают.
4. **Публичный запуск — выполнен.** DNS и релей переключены, сайт доступен.
   Первый автоматический deploy и проверки после него завершены.
5. **Наблюдение.** Старые данные сохранены. Возврат на `front` после новых
   записей требует обратной синхронизации БД/Storage и совместимого AI-кода;
   один возврат DNS не является откатом. Процедура — в [runbook](RUNBOOK.md).

## Границы и дальнейшее сопровождение

- Постоянный автоматический offsite-бэкап не настроен; есть разовая копия на Mac.
- Google OAuth возвращает корректный redirect на accounts.google.com с callback
  `https://api.cycleconnect.cc/auth/v1/callback`; полный вход в браузере не проверялся.
- Локальные изменения предыдущего аудита сохранены отдельно от миграционного
  релиза; они не были выложены вместе с переносом.
- Не включать cron/watchdog старого хоста и не менять другие проекты. Не хранить
  в документе секреты или значения ключей.

## Первое пробное восстановление 01.11.2026 — исторический снимок

Копия размещена на `cc` в `/root/cycleconnect-staging/`, Compose project `cc-stage`,
контейнеры с префиксом `cc-stage-`. Исходный `front` не изменён. Запущены DB,
Auth, REST, Storage, imgproxy, Kong, приложение и тестовый Caddy. Analytics,
Studio, pooler, Realtime и Edge Functions в этом тесте не запускались.

### Изоляция

- Сеть `cc-stage-internal` имеет `internal: true`; внешний HTTP из контейнера
  проверен и недоступен. Снаружи VPS слушает только SSH.
- Docker в этой конфигурации не публикует порт внутренней сети. HTTP-проверки
  выполняются с `cc` на private IP gateway и порт 443, сохраняя исходные Host/SNI.
  IP определяется через `docker inspect cc-stage-gateway`, а не зашит в скрипты.
- Для теста создан отдельный TLS-сертификат на 7 дней; приложение доверяет ему
  через `NODE_EXTRA_CA_CERTS`. Публичный DNS и сертификаты не менялись.
- `cron.launch_active_jobs=off`, обе cron-задачи неактивны, HTTP-очередь пуста.
  SMTP направлен на закрытый localhost, Google OAuth и внешние AI-ключи
  отключены в тестовой конфигурации. Уведомления не отправлялись.

### Повторяемый порядок восстановления

Скрипт `/root/cycleconnect-staging/restore.sh` предназначен только для тестовой
копии на `cc`: пересоздаёт БД в `cc-stage-db`. Перед повторным запуском остановить
остальные тестовые сервисы, чтобы они не меняли данные.

1. Та же версия `supabase/postgres:15.8.1.085`, исходные Compose init SQL и
   `/etc/postgresql-custom` из дополнительного `db-config.tar.gz`.
   Штатной инициализации нужен `pg_net` в preload; изоляцию обеспечивает сеть.
2. Восстановить роли из `globals.sql`, пропуская CREATE существующих ролей,
   сохраняя ALTER/GRANT. Восстановление выполняет `supabase_admin`.
3. В свежую БД восстановить полный `postgres.dump` с владельцами, отложив ACL
   через `--no-acl`. Создать исходную `graphql_public.graphql(text,text,jsonb,jsonb)`
   из `graphql-wrapper.sql`, вернуть её в extension `pg_graphql`: определение
   этой функции отсутствует в обычном dump как объекта расширения.
4. Применить все 1162 ACL/default ACL из TOC дампа, затем `database-settings.sql`.
   Права не пропускаются ради успешного завершения восстановления.
5. Отключить cron, очистить HTTP-очереди, сверить данные до запуска API.

Дополнительные файлы находятся в закрытом `/root/cycleconnect-migration/initial/`.
SQL с паролями, env и значения ключей в репозиторий не входят.

### Что проверено

- Совпали 30 маршрутов, 30 профилей/пользователей, 6 событий, 91 запись
  route_images, 44 заезда и 186 объектов Storage.
- Совпали SHA-256 строк `auth.users`, расшифрованного Vault и флагов ролей.
  Совпали все 109 RLS-политик после нормализации порядка ролей и search_path.
- Auth API: создание подтверждённого временного пользователя, вход по паролю,
  RPC собственного профиля. Анонимное чтение приватной колонки запрещено.
- Storage API: загрузка/скачивание/удаление временной аватарки и скачивание
  всех 186 исходных файлов с проверкой SHA-256. Временный пользователь удалён.
- После тестов повторно сверены исходные счётчики и контрольные суммы.
- `/`, `/routes`, `/events` дают 200; защищённая страница перенаправляет на вход;
  same-origin Supabase proxy возвращает 30 маршрутов.
- Это HTTP/API-проверки, без браузерного теста Google OAuth и внешних интеграций.
- В спокойном режиме ядра стека вместе с ОС занято около 1.2 GiB RAM из 3.7,
  доступно около 2.5 GiB, свободно около 63 GiB диска. Это не нагрузочный тест.

### Storage-бэкапы: обязательное исправление

Первый `storage.tar.gz` сохранил байты, но потерял filesystem xattrs: существующий
GPX отдавал HTTP 500 `ENODATA`. Для восстановления использовать новый
`storage-with-xattrs.tar.gz`. И создавать, и распаковывать его GNU tar с флагами
`--xattrs --xattrs-include='*' --acls --numeric-owner`.
Копия действующего `cc-backup.sh` подтвердила отсутствие этих флагов.
Исправленный скрипт подготовлен в `prepared-ops/cc-backup.sh`, проверен `bash -n`,
но не установлен как cron. До переключения установить исправленный бэкап
и проверить восстановление нового архива. Первый неполный архив помечен в
`initial/README-RESTORE.txt`; его не использовать для Storage.

На момент этого первого теста оставались API-вариант AI и embeddings, SRTM,
Realtime/Edge Functions, исходящий туннель и браузерная проверка. Эти пункты
позже проверялись отдельно; текущие pending собраны в начале документа.

## Первичная проверка Gemini API — 01.11.2026, до интеграции приложения

Новый ключ владельца сохранён только в закрытом каталоге
`/root/cycleconnect-migration/secrets/` на `cc` (700, файлы 600).
`gemini.env` содержит ключ и `GEMINI_MODELS=gemini-3.5-flash-lite`.

- `gemini-2.5-flash-lite` возвращает 404: недоступна новым пользователям,

  получен вектор из 1024 чисел. Размер совместим с текущим столбцом, но старые
