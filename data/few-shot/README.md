# Эталонные описания для few-shot

Эта папка — материал для второй итерации AI-описаний (см. `memory/project_ai_route_descriptions.md`). Здесь лежат структурированные CONTEXT-ы, собранные pipeline-ом из трёх реальных GPX, и пустые «слоты» для твоих эталонных описаний.

Что ты делаешь руками, я не делаю — у меня нет личного «голоса» гида и я никогда не ездил по этим тропам. Твои тексты станут ground truth: тем, что LLM увидит в промпте как пример «вот так надо», и тем, по чему мы потом будем сверять её генерацию (accept-rate, отклонения).

## Как использовать

1. Для каждого маршрута читаешь `CONTEXT` (JSON), пишешь `DESCRIPTION` (проза) рядом, на основе только того, что есть в CONTEXT.
2. Пара (CONTEXT → DESCRIPTION) попадает в промпт как few-shot example.
3. Минимум 2 эталона, желательно 3 — они должны покрывать разные типы маршрутов (см. ниже).

## Жёсткие правила для эталонов

Это станет правилами и для LLM, так что нарушения дороги:

- **Только из CONTEXT.** Не упоминай ничего, чего там нет: ни названий, ни дат, ни рассуждений вроде «возможно, здесь раньше стояла церковь».
- **Если CONTEXT молчит — молчи и ты.** При тонком контексте (route-2) пиши короче (~100 слов), а не выдумывай детали.
- **Безличный тон.** Не «автор отметил», не «по словам того, кто проехал». Просто «по маршруту встречается», «в районе X сохранились».
- **2-е лицо, настоящее время.** «Пересекаешь», «выходишь к озеру».
- **Без маркетинговых эпитетов.** «Захватывающий», «незабываемый», «потрясающие виды» — нельзя.
- **Рельеф — обобщённо, не по километрам.** Дай общую характеристику одной фразой: «спокойный», «настоящая холмистая волна», «без подъёмов». Конкретные км упоминай **только** для **резких/коротких подъёмов**, на которые надо реагировать на велике (готовить лёгкую передачу, не стартовать с разгона).
- **Километры — только там, где они нужны.** Хорошие поводы привязаться к км: резкий тягун, ключевая достопримечательность (Дом Боткина), опасность (грязь, брод), длинный пустой интервал между точками питания. Плохой повод: каждое здание подряд.
- **Структура 2-3 абзаца, 150–250 слов:**
  1. Где, длина, общий характер рельефа одной фразой. Если есть резкие подъёмы — пометь.
  2. Что интересного по пути: достопримечательности, виды, история. По смыслу, не по километрам.
  3. Практика: магазины, кафе, источники воды, опасные участки. Если данных нет — так и сказать («кафе по маршруту не отмечены»).

## Что в CONTEXT можно использовать

Слои в порядке надёжности:

1. **`authorWaypoints`** — твоя авторская курация в MapMagic. Самый высокий trust. Если у автора есть `viewpoint` с именем — это самое ценное, что можно упомянуть.
2. **`settlementsAlongRoute`** — деревни в порядке прохождения, с км. Использовать поимённо.
3. **`namedWaterways`**, **`segments[*].namedFeatures`** — реки, мосты, исторические объекты с именем. Использовать поимённо.
4. **`amenities`** — вода и еда, в практическом блоке.
5. **`climbs`** — точки набора, если есть, в блоке про рельеф.
6. **`segments[*].dominantLandscape`** — фон, в одну-две фразы («идёт через лес», «выходит на поля»).

Чего НЕ использовать:
- `segments[*].landscapeCounts` — это служебка для агрегации, не для человека.
- Числовые координаты `lat/lng` (их в CONTEXT нет в первичных слоях, но если когда-то добавятся — игнорировать).
- `warnings` — это сигнал для генератора, не для текста описания.

## Три типа маршрутов в выборке

Выбраны так, чтобы покрыть разный тип контекста:

| Файл | Характер | Чем интересен как эталон |
|---|---|---|
| `route.context.json` | Озёрный край, 42.6 км, плоский, **15 author waypoints** | Богатый авторский слой: viewpoint, ford, hazard, landmark. Эталон показывает, как опираться на курацию автора. |
| `route-2.context.json` | 56.3 км, плоский, **только 2 author waypoints**, тонкий OSM | Тонкий контекст. Эталон показывает, как писать кратко и не выдумывать. |
| `route-3.context.json` | 51.2 км, **rolling, 476 м набора, 2 climb-а**, без author waypoints | Рельеф доминирует. Эталон показывает, как структурно описать профиль. |

## Формат файлов

Каждый маршрут — три файла:

- `routeN.context.json` — выход pipeline-а (это будет input для LLM)
- `routeN.description.md` — здесь ты пишешь прозу (это будет target output для LLM)
- `routeN.notes.md` — опционально: ремарки «что я учитывал и игнорировал, почему» (нам для отладки)

## Чек-лист перед сдачей эталона

- [ ] 150–250 слов (для тонкого CONTEXT можно меньше)
- [ ] 2–3 абзаца
- [ ] Все упомянутые имена реально есть в CONTEXT (проверь grep-ом)
- [ ] Рельеф описан общо; конкретные км — только для резких подъёмов / опасностей / ключевых точек
- [ ] Нет маркетинговых прилагательных
- [ ] Нет упоминания «автор отметил»; тон безличный
- [ ] 2-е лицо, настоящее время
- [ ] Магазины/кафе/вода прямо упомянуты — есть они или нет
- [ ] Прочитать вслух — звучит как гид, а не как реклама
